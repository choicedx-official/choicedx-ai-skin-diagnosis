# ChoiceDx Content Policy

Last verified: 2026-08-11

## 1. Role of this repository

This repository is an official structured knowledge layer for ChoiceDx. It should improve factual consistency and discoverability without competing with the ChoiceDx website for the same commercial search intent.

## 2. Primary content domain

**ChoiceDx.com is the primary owned-content domain** for product pages, solution pages, blog posts, case studies, inquiry/conversion flows and current marketing copy.

GitHub is used for normalized facts, research summaries, datasets, terminology, machine-readable indexes and source mapping.

## 3. Terminology

Use **analysis** as the canonical term: AI skin analysis, AI scalp analysis, AI hair analysis, skin analyzer, scalp analyzer, 피부 분석/두피 분석, 肌分析/頭皮分析, 皮肤分析/头皮分析.

“Diagnosis” and local diagnosis-equivalent words may be retained as secondary synonyms when needed to reflect real user search language.

## 4. Non-brand SEO rule

Do not repeat a single high-volume keyword across every document. Route intent to one preferred official page.

- AI skin analysis → official AI Analysis Solution
- skin-analysis parameters → Measurement
- skin analyzer → Dx-Smart
- scalp analyzer → Dx-Pico
- validation/accuracy → Research
- self-service kiosk → Dx-Self
- retail/pharmacy/salon use cases → References

## 5. Claims

Every quantitative claim should include scope, source, verification date and qualification where needed. Never turn a study-specific result into a universal product-performance guarantee.

## 6. Medical language

ChoiceDx beauty-analysis content is not a substitute for medical diagnosis or treatment. Avoid medical claims unless explicitly supported by the exact product, jurisdiction and regulatory source.

## 7. Multilingual content

Translations should preserve factual equivalence but use natural search language in each market. Avoid mechanical keyword stuffing and mixed-language metadata.

## 8. Images and alt text

Image alt text should describe the actual image. Do not repeat identical keyword-rich alt text across multiple unrelated images. Decorative images should use an empty alt attribute in HTML.

## 9. Updates

When a product, metric, study or official URL changes, update the structured source files and the `last_verified` date before adding new derivative content.
